# Font & License Registry — Arabic Calligraphy Studio

Every font bundled in `assets/fonts/calligraphy/` comes from Google's
[`google/fonts`](https://github.com/google/fonts) repository (the same
files served by fonts.google.com) and ships under the **SIL Open Font
License 1.1 (OFL-1.1)**. The OFL explicitly permits embedding fonts in a
website (as a web font) and redistributing them, unmodified or modified,
as long as the fonts are not sold by themselves and any modified
versions are renamed — both conditions we respect (we redistribute the
files unmodified, converted only to WOFF2, and keep their original
names). Each family below has its own `OFL.txt` sitting next to it in
`assets/fonts/calligraphy/<family>/`; that file is the authoritative
license text and travels with the font.

**Do not add any font to this project that is not covered by an explicit,
verifiable open license permitting web embedding and redistribution.**
When adding a new family, copy its official `OFL.txt` (or other license
file) into its folder and append a row to the table below — that is what
keeps this registry trustworthy.

## Audit methodology (this pass)

Two separate questions had to be answered honestly for every font in the
table above, and the answers are what `calligraphy-data.js` is generated
from — nothing in that file is hand-guessed:

**1. Which fonts genuinely exist under a redistributable license?**
Every candidate (rows 26–32 are new in this pass) was resolved against
the live `google/fonts` GitHub repository — the same source
fonts.google.com serves from — fetching its actual `METADATA.pb`,
`DESCRIPTION.en_us.html`, and `OFL.txt` rather than trusting a font's
reputation. `Alkalami` in particular is not one of the calligraphy
families originally requested (Diwani, Jali Diwani, Ijazah, Shekasteh,
Andalusi, Maghribi, Muhaqqaq, Rayhani) — it's a distinct West African
Ajami/Kano calligraphic hand (SIL International, documented as based on
the local "qalam" sharpened-stick writing tradition of the Kano region).
It's listed under its own honest family name, not mislabeled as a
substitute for Andalusi or Maghribi, which — despite another real
search pass this round — still have no verifiably-licensed open
digitization we could find.

**2. Which OpenType features on each font actually change Arabic
glyphs?** A font's GSUB feature list can include tags (`ss01`, `cv01`,
`salt`, `dlig`, `frac`, `sups`, ...) that are registered but either (a)
only apply to non-Arabic glyphs bundled in the same file (digits,
fractions, Latin), or (b) are registered for the script but don't
actually trigger any substitution on real Arabic text. Listing every
registered tag as a "variation" would mean shipping cards that look
identical to the default. To avoid that, every font in
`assets/fonts/calligraphy/` was:

1. Parsed with `fontTools` to list every feature tag registered under
   the font's `arab` (or `DFLT`) GSUB script table — this is the
   candidate list, not the final one.
2. Converted to a plain TTF and shaped with `uharfbuzz` (the actual
   HarfBuzz shaping engine — the same one Chromium and Firefox embed)
   against four representative phrases: بسم الله الرحمن الرحيم, محمد
   رسول الله, ما شاء الله, السلام عليكم ورحمة الله وبركاته — once with
   the feature off, once with it forced on.
3. A feature only survives into `calligraphy-data.js` as a variation if
   that shaping pass produced a **different glyph-ID sequence** on at
   least one of the four phrases. Everything that came back identical
   (e.g. `liga`/`rlig` on fonts where they're already always-on by
   default, or digit/fraction features like `sups`/`ordn`/`frac` that
   never touch Arabic letters) was dropped rather than shown as a fake
   card.

This is stricter than a visual check — it's an exact glyph-ID diff
against the real shaping engine — and it's why family variation counts
vary so much (Tholoth has zero genuine OpenType variations and shows
only its one real font; Amiri has two; Aref Ruqaa has five). The full
per-font table produced by this pass:

size only — no outlines, metrics, or hinting were modified, and no
license text was altered. Original `.ttf` sources are not bundled to
keep the site light; they can always be re-fetched from the `Source`
links above if needed (e.g. to regenerate the WOFF2 files or to produce
a print-quality PDF pipeline later).

### Note on #24–25 (GPL v2, not OFL)

Tholoth and Cortoba come from the Arabeyes **Khotot** project — a
long-standing (2004–2006) open Arabic-font collection, packaged as
`fonts-arabeyes` in Debian/Ubuntu's `universe` archive ever since, and
still the only genuine, cleanly-licensed **Thuluth** digitization we
could find (see "Categories we deliberately left out" below for what we
searched and ruled out for the other five categories). Its license is
**plain GNU GPL v2**, not the OFL used everywhere else in this
project. That is a real, meaningful difference and is called out
explicitly rather than folded into the OFL rows above:

- GPL v2 explicitly permits verbatim redistribution of the unmodified
  font file (§1 of the license) — which is exactly what this project
  does (TrueType → WOFF2 only, no outline/glyph edits), so bundling
  and serving these two files is squarely inside what the license
  allows.
- Unlike the OFL fonts, GPL v2 has no "don't sell the font by itself"
  clause and no reserved-name clause — but it also lacks the OFL's
  explicit "embedding fonts in a document does not GPL the document"
  carve-out. Whether *rendering text with a GPL font* obligates the
  *rendered artwork* under GPL is a genuinely debated question in
  font-licensing circles, with no binding precedent; our reading (and
  the reading under which Debian/Ubuntu/Fedora have shipped GPL fonts
  as system fonts for two decades) is that it does not, since a font
  is a tool applied to the user's own text, not a work the user's text
  becomes "based on." We are not lawyers and this is not legal advice
  — see "Fair use" caveat in the project's general disclaimers.
- The full GPL v2 text is bundled at
  `assets/fonts/calligraphy/tholoth/GPL-2.txt` and
  `assets/fonts/calligraphy/cortoba/GPL-2.txt`, alongside the
  Debian-packaged copyright/attribution file for each.

If a cleaner OFL/Apache/public-domain Thuluth digitization surfaces
later, it should replace Tholoth rather than sit alongside it, to keep
the collection's licensing story simple.

## Categories we deliberately left out (for now)

The user brief (across two passes) asked for **Naskh, Thuluth, Diwani,
Diwani Jali, Ruq'ah, Kufi, Muhaqqaq, Rayhani, Maghribi, Andalusi,
Persian/Nastaliq, Ijazah, and Shekasteh**. Naskh, Thuluth, Ruq'ah, Kufi,
and Persian/Nastaliq are covered above (Thuluth via Tholoth, #24 — the
one exception to "prefer OFL," noted explicitly rather than mislabeled
as something it isn't). For the remaining seven — **Jali Diwani,
Diwani, Ijazah, Shekasteh, Andalusi, Maghribi, Muhaqqaq, and Rayhani**
— this pass repeated the search (OFL/GPL/public-domain Arabic type
projects, the full `google/fonts` repository, Debian/Ubuntu/Fedora font
packages, SIL and Arabeyes archives) and still could not find a
genuine, legally-clear open-license digitization of any of them. What
exists in wide circulation for Diwani/Jali Diwani/Ijazah/Shekasteh is
commercial or license-unclear (e.g. Decotype, Diwan Software, and
various "free for personal use" download sites with no verifiable
rights holder). "Andalusi/Maghribi" calligraphy specifically has
essentially no open digital revival we could locate — the historical
Maghribi script tradition (Fes/Fez, Cordoba, Granada, Kairouan
lineages) has not, as far as we found, been faithfully digitized under
an open license; a couple of Arabeyes fonts named after Andalusian
cities (Cortoba, Granada) exist, but on inspection **Granada's glyphs
render broken/overlapping in real Arabic joining** (see rendering QA
below) so it was excluded outright, and **Cortoba is a bold decorative
display face, not an authentic Maghribi/Andalusi hand** — so it is
listed honestly above under "Decorative," not relabeled "Andalusi."
**Muhaqqaq and Rayhani** (newly requested this pass) have essentially
no digital revival of any kind that we could locate, open or otherwise
— historically they're calligrapher-only hands even more than
Diwani/Ijazah are. Rather than mislabel a font or fabricate
stylistic-set variations that don't exist, the Studio marks all eight
of these categories **"قريبًا" (Coming soon)** with a short note, and
the architecture (`CALLIGRAPHY_FAMILIES` in `calligraphy-data.js`) is
built so a family can be added the moment a verifiably-licensed font is
found — see "Adding a new family" in `ARCHITECTURE.md`.

One family not on the original list — **Ajami/Kano** (Alkalami, #28
above) — surfaced during this pass's research and was added under its
own real name rather than discarded, since the brief explicitly welcomed
"other legitimate Arabic calligraphic families discovered during
research."

### Rendering QA performed before adding #21–25

Every candidate font pulled in during this pass (all ~30+ fonts in the
`fonts-arabeyes`/Khotot package, plus Thabit, IranNastaliq, and Amiri
Quran) was actually installed and rendered with a real Arabic-shaping
engine (WebKit/HarfBuzz via `wkhtmltoimage`) against both acceptance
phrases — بسم الله الرحمن الرحيم and محمد رسول الله — before being
added to the registry. Fonts that rendered with broken/overlapping
glyphs under real contextual joining (notably **Granada** and
**Haramain** from the same Khotot package, and **AlManzomah**) were
rejected and are not bundled, even though they carry the same GPL v2
license as Tholoth/Cortoba — a valid license does not make a broken
font file acceptable to ship.

"Persian" as a family is intentionally mapped to Gulzar / Noto Nastaliq
Urdu / Mirza (Naskh, Persian-influenced) rather than a separate
synthetic category, since Persian calligraphy uses the same
Nastaliq/Naskh scripts already represented — a dedicated "Persian"
bucket would otherwise just be a relabeling of the same fonts.

### Rendering QA performed before adding #26–32 (this pass)

Every new font (Mirza, Qahiri, Alkalami, Vibes, Lemonada, Baloo
Bhaijaan 2, Lalezar) was shaped through `uharfbuzz` against all four
acceptance phrases and confirmed to produce zero `.notdef` (missing
glyph) codepoints — i.e. every glyph the phrases need actually exists
and joins in the font — before being added to the registry or the
OpenType feature audit table above.

## Adding a new family later

1. Confirm the license explicitly allows web embedding **and**
   redistribution (OFL, Apache 2.0, and most SIL licenses qualify;
   "free for personal use" or unclear licenses do not).
2. Copy the license file into `assets/fonts/calligraphy/<family-id>/`.
3. Add the WOFF2 file(s) next to it.
4. Add one row to the table above.
5. Run the audit: `fontTools` to list the font's GSUB features for the
   `arab` script, then `uharfbuzz` to shape the four acceptance phrases
   with each candidate feature on vs. off and keep only the ones that
   produce a different glyph-ID sequence (see "Audit methodology"
   above for the exact approach and the reference table of what this
   produced for every font currently in the project).
6. Register the family + only the *confirmed-genuine* variations
   (weights that are real named `fvar` instances or real separate
   files, features that passed step 5 — never fabricated ones) in
   `assets/js/calligraphy-data.js`, using `FEATURE_LABELS` for the
   `meta`/`metaEn` description so the UI shows the real OpenType
   feature name.
